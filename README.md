# GROK Factory

The copyable operating system for the next product. Distilled from [Otto](https://github.com/VirBk/Otto) and [Virbos](https://github.com/VirBk/virbos), which remain read-only references.

**Start at [`AGENTS.md`](AGENTS.md).** Then `BOARD.md`, then your envelope.

This repository is the factory, not the product. Product work starts when the owner drops a spec. Until then, idle is success.

## What this is for

The next project copies this kit instead of reinventing seating, reviews, landing, and the record. The bar is the [assessment](factory/ASSESSMENT.md): ten dimensions, forty checks, six hard fails. Ten is a gate, not a vibe.

## Copy

See [`factory/COPY.md`](factory/COPY.md). In short: copy `AGENTS.md` and `factory/`, leave Otto and Virbos where they are, fill the product paragraph, name the never-move rules, wire `landing-checks.json` to the new stack, score the empty factory, then wait for a spec.

Do not copy `BOARD.md` contents or any `SESSION_LOG`. Start a new `factory/board.json`.

## What was kept, killed, and changed

Kept: envelope as authorization, three-file reading, control plane split, live-main worktrees, correction cap, closed keystones, idle-is-success, the short owner-ask list, contracts as product, real-data gates, authority levels, walkthrough as acceptance.

Killed: `SESSION_LOG.md`, copied counts, documentation as a lane, permanently red CI, issuing from an unlanded tip, invented clocks, rules with no check.

Changed: the board is JSON, the landing gate runs from a fresh archive of the commit, holds are proved at issue, long jobs are polled in the foreground, a Linux compile is named as the platform adversary.

## Size

Live files have caps. The landing gate fails a commit that breaks them. Counts are not typed in this README; derive them when you need them.
